SECTION 1: EXECUTIVE VERDICT
================================================================================
Salvus is an emergency-response software system featuring a deterministic mechanical core, strict finite state machines, a first-class assignment lifecycle, auditable scoring formulas, real-time WebSocket synchronization, and Leaflet/OSRM geospatial integration.

Unlike typical hackathon projects that build flimsy CRUD apps or chatbot wrappers, Salvus has built:
1. A mathematical, auditable allocation engine that does not delegate life-or-death dispatch decisions to stochastic LLMs.
2. First-class transactional domain models (incidents, assignments, responders, shelters, incident_events, ai_triage_assessments) backed by SQLite WAL mode.
3. Synchronized dual-portal frontend architectures (Citizen Safety & Authority Command Center) with out-of-order packet guards and reconnect recovery.
4. 164 automated backend tests validating state machine transitions, allocation formulas, candidate filtering, and real-time dispatch loops.

MASTER QUESTION: IS SALVUS ACTUALLY READY FOR THE AI / INTELLIGENCE PHASE?
VERDICT: CONDITIONALLY READY (READINESS SCORE: 86 / 100)

The mechanical and architectural foundation is strong. However, 4 critical blockers must be resolved before introducing production AI models:
1. Security & Actor Authorization: The API relies on client-provided actor="authority" body parameters with zero cryptographic authentication (no JWT/sessions). Anyone can trigger dispatch or override triage.
2. Frontend API Key Exposure Vulnerability: Root .env.example suggests VITE_GEMINI_API_KEY for client bypass, which would leak API secrets in the client bundle. All AI calls must terminate strictly on the backend.
3. Monolithic Authority UI Component: AuthorityCommandCenter.jsx has swelled to 1,875 lines (84.8 KB), making it difficult to integrate live multi-agent AI streams without UI regression.
4. Synchronous AI Service Ingestion: AI triage is executed synchronously within the incident creation pipeline (with a 4-second timeout). It must be shifted to an asynchronous background task queue to prevent slow LLM responses from delaying distress beacon persistence.

SECTION 6: DATABASE AUDIT
================================================================================
Engine: SQLite with WAL mode (PRAGMA journal_mode=WAL; PRAGMA foreign_keys=ON).
Database File: backend/data/salvus.db

Core Tables:
1. `incidents`: Emergency distress beacons and hazard reports.
   - Primary Key: id (TEXT UUIDv4)
   - Unique: ticket_id (e.g. SV-2048)
   - Columns: type, severity, description, reporter_name, reporter_phone, latitude, longitude, affected_count, is_sos, status, created_at, updated_at
2. `incident_events`: Immutable audit trail logging every state transition.
   - Primary Key: id (TEXT UUIDv4)
   - Foreign Key: incident_id -> incidents(id) ON DELETE CASCADE
   - Columns: event_type, previous_status, new_status, actor, metadata, created_at
3. `responders`: Active rescue units, ambulances, and response teams.
   - Primary Key: id (e.g. resp-101)
   - Columns: unit_name, team_lead, vehicle_type, capability, status, latitude, longitude, radio_channel, max_capacity, current_load, assigned_incident_id, last_seen, created_at, updated_at
4. `assignments`: First-class domain entity linking one incident to one responder.
   - Primary Key: id (TEXT UUIDv4)
   - Foreign Keys: incident_id -> incidents(id), responder_id -> responders(id)
   - Columns: status, assigned_by, assigned_at, accepted_at, started_at, nearby_at, arrived_at, completed_at, cancelled_at, score, score_breakdown, assignment_reason, created_at, updated_at
5. `shelters`: Evacuation shelters and disaster relief stations.
   - Primary Key: id (e.g. shl-01)
   - Columns: name, address, latitude, longitude, total_beds, available_beds, occupancy_rate, supplies_status, status, is_active, created_at, updated_at
6. `ai_triage_assessments`: Audit logs of AI triage evaluations and human reviews.
   - Primary Key: id (TEXT UUIDv4)
   - Foreign Key: incident_id -> incidents(id) ON DELETE CASCADE
   - Columns: model_name, provider, severity_level, recommended_capability, priority_reasoning, confidence, uncertainty_flags, is_actionable, review_status, reviewed_by, reviewer_notes, created_at, updated_at

Indexes:
- idx_incidents_status, idx_incidents_coords, idx_incidents_created_at
- idx_incident_events_incident_id
- idx_responders_status, idx_responders_assigned
- idx_assignments_incident, idx_assignments_responder, idx_assignments_status

SECTION 8: STATE MACHINE AUDIT
================================================================================
Lifecycle State Graphs:

INCIDENT:
  NEW -> TRIAGE_PENDING -> VERIFIED -> ASSIGNED -> EN_ROUTE -> NEARBY -> ON_SCENE -> RESOLVED
  NEW | TRIAGE_PENDING | VERIFIED | ASSIGNED | EN_ROUTE | NEARBY | ON_SCENE -> CANCELLED

ASSIGNMENT:
  PROPOSED -> ASSIGNED -> EN_ROUTE -> NEARBY -> ON_SCENE -> COMPLETED
  PROPOSED | ASSIGNED | EN_ROUTE | NEARBY | ON_SCENE -> CANCELLED

RESPONDER:
  AVAILABLE -> ASSIGNED -> EN_ROUTE -> NEARBY -> ON_SCENE -> AVAILABLE
  AVAILABLE -> OFFLINE -> AVAILABLE

Out-of-Order Guards:
Frontends implement numeric state ranking (STATUS_RANKS). Packets arriving with a lower status rank than current state are rejected to prevent network replay regressions.

SECTION 17: SECURITY AUDIT
================================================================================
Vulnerability Findings & Remediations:
1. No Authentication on Mutation Routes (CRITICAL / P0):
   - Finding: Anyone can send {"actor": "authority"} to dispatch units or resolve incidents.
   - Remediation: Implement JWT Bearer token authentication with role claims.
2. Frontend Template Secret Exposure (HIGH / P0):
   - Finding: Root .env.example contains VITE_GEMINI_API_KEY and VITE_GROQ_API_KEY.
   - Remediation: Remove AI keys from the frontend template; all AI inference must stay behind backend routes.
3. Unauthenticated WebSocket Rooms (HIGH / P1):
   - Finding: Any WebSocket client can join the "authorities" room.
   - Remediation: Validate auth tokens on connection and room join events.
4. PII in External AI Prompts (MEDIUM / P1):
   - Finding: Phone and email are redacted via regex, but citizen names could still be passed.
   - Remediation: Add named-entity scrubbing before calling external LLM providers.

SECTION 37: JUDGE Q&A RISKS & ANSWERS
================================================================================
Q: Why use AI for triage instead of a simple form?
A: During disasters, frantic citizens submit unstructured, panic-driven text or voice notes. AI extracts critical signals (water depth, trapped counts, medical needs), identifies required equipment capabilities, and estimates urgency in milliseconds, allowing dispatchers to prioritize hundreds of incoming distress calls.

Q: Why not let AI dispatch the rescue boats directly?
A: Dispatching life-safety assets is high-risk. Generative models can hallucinate. Salvus uses AI strictly for decision support, while asset allocation is governed by a deterministic, mathematically auditable 100-point scoring formula with mandatory human dispatcher authorization.

Q: What happens if external AI APIs or cell networks fail?
A: Salvus implements a multi-tier fallback architecture. If Gemini is unreachable, it falls back to Groq; if Groq fails, it degrades to deterministic keyword heuristics. If cell connectivity drops, the client caches last-known coordinates and displays reassurance notices while the backend preserves queue position.

Q: What happens if GPS is inaccurate or denied?
A: Salvus translates raw GPS accuracy into humanized tiers (High Precision ±4m, Approximate). If geolocation is denied, the user can select from a curated list of local landmarks (e.g., Sector 12 Community Hub) to ground the distress report.
